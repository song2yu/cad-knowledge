03

关键洞察

Key takeaways

① 从 DSL 到「原生 Python」是决定性转向

早期 CSGNet（2018）、Shape2Prog（2019）用受限 DSL，表达力有限；Fusion 360 Gallery（2021）用厂商封闭语言；2024 年后 CAD-Recode、CAD-Coder、Zero-to-CAD 全面转向 CadQuery / FreeCAD 等功能完备的 Python 库——模型可以直接复用海量代码语料上预训练的编程知识，操作表达力也不再受限。

② 「执行反馈」是保证代码可用的关键机制

代码生成最大的坑是「能跑但不对」甚至「跑不通」。解决方案高度一致：让 LLM 在真实执行环境中迭代——Query2CAD 用 BLIP2 反馈精修（成功率 +23.1%）；CAD-Coder 用 GRPO 以 Chamfer 距离 + 可执行性作奖励；Zero-to-CAD 让 LLM 读异常堆栈、查 API 文档、修代码（每个零件最多 100 次尝试）；Seek-CAD 渲染每步中间形态做视觉反馈。「生成 → 执行 → 反馈 → 修正」闭环已成标配。

③ 数据从「百万硬编码」进化到「百万可读」

CAD-Recode 的 100 万代码多是硬编码坐标（r = w0.sketch().segment((...),...)，机器能跑人改不动）；Zero-to-CAD 的 100 万程序则带命名参数与逻辑结构（plate_length = 60.0; hole_diameter = 8.0，改孔径只需改一行）。「可读可编辑」正成为新一代数据集的核心卖点。

④ 开源工具链已可落地生产

text-to-cad（16K+ Stars，MIT）证明这条链路不只是论文：Agent 写 build123d 源码 → 执行出 STEP → inspect/validate/snapshot 检查 → 支持导出 STL/3MF/URDF/SDF 一直到切片打印。产物是可 git diff 的源码，改需求 = 改一行参数，全流程本地运行。学术侧 BenchCAD / CADExpert 则提供了执行验证过的评测标准。
