🧭 全景速览：两套并行体系

ms-swift（Transformers 系）

DDP、device_map、DeepSpeed ZeRO、FSDP/FSDP2、序列并行（Ulysses / Ring-Attention）。

Megatron-SWIFT（Megatron-LM 系）

TP、PP、SP、CP、ETP、EP、VPP 全套并行策略，大规模集群 / MoE 提速。

📡 基础：集合通信原语速查

所有并行策略都建立在几个集合通信原语之上，理解它们是看懂一切原理图的前提：

原语动作典型用途
Broadcast 广播1 张卡的数据复制发给所有卡ZeRO-3 前向传播时"借"参数
Scatter 散射1 张卡的数据切块分发给各卡数据分片
Gather 聚合各卡数据拼到 1 张卡（不求和）结果汇总
Reduce 规约各卡数据发到 1 张卡并求和局部汇总
All-Reduce 全规约各卡数据求和后全员同步DP 梯度同步（= Reduce-Scatter + All-Gather）
All-Gather 全聚合各卡分片拼成完整数据，人人有份ZeRO-3 / FSDP 取回完整权重
Reduce-Scatter 散射规约求和后再按分片分发ZeRO-2 / FSDP 梯度分片
All-to-All 全交换各卡数据互相交换（像矩阵转置）Ulysses 序列转置、EP 专家调度

🔬 原理详解：六大并行策略

1️⃣ 数据并行 DP —— 模型复制，数据分片

每张 GPU 放一份完整模型副本，把 mini-batch 切成 micro-batch 分给各卡独立算，最后用 All-Reduce 同步梯度。实现最简单、吞吐提升直接，但每张卡都要存完整状态：

单卡显存 ≈ Ψ(参数) + Ψ(梯度) + K·Ψ(优化器状态) （Adam 混合精度 K≈12：FP32 参数 4B + 一阶动量 4B + 二阶动量 4B）

2️⃣ ZeRO —— 消除数据并行的冗余（切状态）

核心洞察：DP 里每张卡的状态是重复的，那就切开存。三阶段逐级深入：

阶段切什么通信量变化要点
ZeRO-1优化器状态 ÷ N略增（All-Reduce 后追加 All-Gather）最保守，参数/梯度仍全量
ZeRO-2+ 梯度 ÷ N与 DP 完全相同（Reduce-Scatter 替代 All-Reduce）显存通信双赢，最常用
ZeRO-3+ 参数 ÷ N增加约 50%（前向/反向都要 All-Gather 借参数）显存最省，可训万亿参数；通信换显存
ZeRO-3 单卡静态显存 ≈ (Ψ + Ψ + K·Ψ) / N —— 理论上 N 足够大就能装下任意大模型

延伸：ZeRO++（节点内模型分片）、ZeRO-Offload（卸载到 CPU）、DeepSpeed AutoTP。

3️⃣ FSDP / FSDP2 —— PyTorch 原生的 ZeRO-3

与 ZeRO-3 同思想，但工作流按层为单位动态取还参数：

前向：for layer_i:  All-Gather 权重 → 前向计算 → 立即丢弃非本卡分片
反向：for layer_i:  All-Gather 权重 → 反向计算 → Reduce-Scatter 梯度

FSDP2 用 fully_shard + DTensor + DeviceMesh 实现按参数分片，替代 FSDP1 的 FlatParameter，更省显存、调试更友好。ms-swift 中 --fsdp 'fsdp2' 一行开启。

4️⃣ 张量并行 TP —— 层内切分矩阵

把单层的权重矩阵按行/列切开分到多卡（分块矩阵乘法）。Megatron 经典组合：第一个线性层按列切 + 第二个线性层按行切，中间只需一次通信；Attention 按头天然切分。Embedding 按词表切、交叉熵分块计算（Flash Attention 同思想）。

⚠️ TP 每层前向/反向都要通信，对带宽极其敏感 → 限制在节点内（NVLink），TP 度数一般 ≤ 8，不跨节点。

5️⃣ 流水线并行 PP —— 层间切分 + 微批次填充

把模型按层垂直切成多段放不同卡，数据像流水线流过。朴素流水线同一时刻只有一张卡在算，浪费严重；用 micro-batch 填充和 1F1B 调度（前向一次紧跟反向一次）压气泡：

气泡率 ≈ (PP − 1) / (M + PP − 1) M = micro-batch 数，M 越大气泡越小

VPP 虚拟流水线：一张物理卡虚拟多个不连续层段，气泡进一步压缩。PP 层间只传激活值，通信量小，可以跨节点。

6️⃣ 序列并行 SP / CP + 专家并行 EP

技术原理关键特性
UlyssesQ/K/V 沿序列维切分，用 All-to-All 做分布式转置，变成按注意力头切分通信量与序列长度线性、与卡数无关；受头数整除限制（可与 Ring-Attention 结合解除）
Ring-Attention序列分块，各卡持一块，环形 P2P 传递 K/V，分块计算注意力（在线 softmax）通信与计算重叠，显存极省；因果掩码下用 zigzag 切分均衡负载
Megatron SP只切 LayerNorm/Dropout 段，与 TP 配合（一次 All-Reduce = Reduce-Scatter + All-Gather）不增加通信量的同时降低激活显存
CP 上下文并行面向 128K/256K 极致长上下文的 Ring 类方案工业级长文本标配
EP 专家并行MoE 的专家集合分片到多卡；Top-k 路由 → Dispatch All-to-All → 专家计算 → Combine All-to-All不切单层权重，只切专家集合；MoE 提速关键

🧩 4D 并行：组合拳

实际大模型训练是 DP × TP × PP ×（SP/CP/EP）多维正交组合：TP 限制在节点内、PP 可跨节点、DP 兜底扩数据规模，SP/CP/EP 处理长文本与 MoE。例如 70B 模型预训练常见配置：ZeRO-3 + TP + PP 三重并行。

❓ 常见问题问答（实战判断）

Q1　ZeRO-1/2/3 能降低显存需求，但不能加快训练速度，对吗？

基本正确，但要精确一点。ZeRO 的本质是「用通信换显存」：

阶段显存速度说明
ZeRO-1✅ 略降➖ 基本不变通信量略增（多一次 All-Gather）
ZeRO-2✅✅ 明显降➖ 基本不变通信量与 DP 持平（Reduce-Scatter 替代 All-Reduce），最受欢迎
ZeRO-3✅✅✅ 最省🐢 略慢前向/反向都要 All-Gather 借参数，通信量约 +50%

重要例外：若不开 ZeRO 就 OOM 跑不起来，那「能跑起来」本身就是最大加速（从 0 到 1）。此外省下的显存可换更大 batch size，间接提升吞吐。

Q2　offload 是什么时候把权重卸载到 CPU？

分两种，时机不同：

类型卸载对象时机
ZeRO-Offload（优化器卸载）优化器状态 + 梯度GPU 算完梯度后搬到 CPU 做优化器更新，更新完再把参数搬回 GPU
ZeRO-3 Offload / FSDP CPU Offload模型参数参数用完立即卸载：某层前向算完，该层参数马上从 GPU 挪到 CPU；下次要用再搬回来

一句话：offload 是「用完即卸、要用再取」的按需搬运，用 PCIe 带宽换显存。代价是 CPU-GPU 传输慢，训练速度可能下降 2-5 倍，属于显存实在不够时的最后手段。

Q3　DP 中模型复制，总 batch size=16、4 张卡，是每卡负责 4 个样本吗？

完全正确 ✅

  • 总 batch size = 16，DP = 4 → 每张卡分到 16 / 4 = 4 个样本
  • 每张卡用完整模型副本独立计算这 4 个样本的前向 + 反向
  • 最后 4 张卡的梯度通过 All-Reduce 求和/平均，得到全局梯度，各卡同步更新
⚠️ 若开启梯度累积（如 gradient_accumulation_steps=2），每卡每步只处理 2 个样本，累积 2 步才更新一次，等效 batch 仍是 16。
Q4　TP 中是怎么切分权重的？（含示意图）

核心：分块矩阵乘法，按行切或按列切。以 Y = XW 为例：

按列切 → 第二个线性层按行切，中间仅需一次通信，效率最优
切分方式输入 X输出 Y通信
按列切 W复制到每张卡按列拼接无（concat）
按行切 W按列切分求和一次 All-Reduce

补充：Attention 天然按多头切分（每个头独立计算）；Embedding 按词表切分；交叉熵损失也做分块计算（与 Flash Attention 同思想）。

Q5　不深究 infra，哪些并行是为了省显存？哪些会变慢？
策略省显存速度影响一句话建议
DDP❌ 不省⚡ 快（线性加速）模型装得下就用它
ZeRO-1✅ 省一点➖ 基本不变保守选择
ZeRO-2✅✅ 省很多➖ 基本不变⭐ 首选，显存通信双赢
ZeRO-3✅✅✅ 最省🐢 略慢（通信+50%）模型太大装不下时用
FSDP2✅✅✅ 最省🐢 略慢（同 ZeRO-3）PyTorch 原生替代方案
Offload✅✅✅✅ 极致省🐢🐢 明显变慢最后手段
TP✅✅ 省🐢 慢（通信密集，需 NVLink）单卡放不下单层时用
PP✅✅ 省🐢 慢（有气泡）跨节点扩展用
序列并行✅✅ 省➖ 基本不变长文本必用，几乎无额外开销
🎯 结论一句话：省显存且不减速 → ZeRO-2、序列并行；省显存但会变慢 → ZeRO-3、FSDP2、TP、PP、Offload。
